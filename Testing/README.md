1. 关于数据库 | About

本数据库用于收集、整理和记录 Android AI 聊天应用的实际使用情况，重点关注 AI 伴侣、角色扮演、角色聊天及 NSFW 相关功能。

This database documents and evaluates Android AI chat applications, focusing on AI companions, roleplay, character chat, and NSFW-related features.

数据库采用两种展示方式：

- 实测总览 / Test Overview：通过统一表格比较不同应用。
- 独立实测档案 / Detailed Application Profiles：为每款应用保存完整测试记录。

The database provides two presentation formats:

- Test Overview: Standardized tables for comparing applications.
- Detailed Application Profiles: Individual records containing comprehensive test results.

3. 实测原则 | Testing Principles

3.1 信息来源 | Information Sources

所有数据必须明确区分来源：

- 用户实测 / User-reported Test
- 官方资料 / Official Information
- 第三方资料 / Third-party Information

All records must clearly identify whether information comes from hands-on testing, official documentation, or third-party sources.

3.2 独立记录不同功能 | Separate Feature Evaluation

以下项目必须分别记录，不得相互替代：

- 私人聊天是否支持 NSFW 生成。
- 是否需要手动开启 NSFW 设置。
- 成人内容是否触发警告或限制。
- 公开角色和公开简介是否展示成人描写。
- 应用是否提供 NSFW 相关标签。
- 标签是否支持搜索及筛选。

The following must be evaluated independently:

- NSFW generation in private conversations.
- Whether NSFW settings must be enabled manually.
- Adult-content warnings and restrictions.
- Adult descriptions in public characters and profiles.
- Availability of NSFW-related tags.
- Tag search and filtering capabilities.

3.3 测试环境 | Testing Environment

每次测试应尽可能记录：

中文| English
测试日期| Test Date
应用版本| App Version
Android 版本| Android Version
测试地区| Test Region
账户设置| Account Settings
测试场景| Test Scenario
测试结果| Test Result

Each test should record its date, application version, Android version, region, account settings, test scenario, and results whenever possible.

3.4 避免未经证实的结论 | Avoid Unsupported Claims

没有经过实际测试的项目，不得标记为已支持或不支持。

Features that have not been tested must not be labeled as supported or unsupported without sufficient evidence.

5. 证据等级 | Evidence Levels

为避免混淆，采用以下证据标记：

等级| 标记| 说明
E1| Official| 开发者官方资料
E2| Hands-on| 实际安装与操作测试
E3| Third-party| 第三方公开资料
E4| Unconfirmed| 尚未获得可靠证据

Evidence labels identify the origin of information. They do not automatically indicate that a feature is better or more reliable.

特别说明： 用户实测结果与官方说明发生冲突时，应分别保留两种记录，并注明测试环境，不应擅自覆盖其中任何一方。

When hands-on results conflict with official documentation, both records should be preserved with their respective sources and testing conditions.

6. 数据更新 | Database Updates

- 应用更新后，应重新核实受影响的功能。
- NSFW 设置发生变化时，应更新相关记录。
- 下载链接失效时，应及时修正。
- 收费方式变化时，应更新价格记录。
- 历史测试结果应保留，不应直接删除。

Application updates, changes to NSFW settings, broken download links, and pricing changes should be documented.

Historical test records should be preserved rather than silently overwritten.
